# FrameWatch 0.3.1

Окремий клієнтський мод для **Minecraft 1.7.10 / Forge 10.13.4.1614**. Монітор для GTNH: темні напівпрозорі панелі, білий піксельний текст, зелено-жовто-червоний графік часу кадрів, статистика, JVM/GC і CSV. Повноцінне меню налаштувань: масштаб, прозорість, незалежне розташування двох панелей і перемикачі блоків. Мову HUD і меню можна обрати окремо від Minecraft; RAM купи JVM і Direct мають незалежні перемикачі. Серверна частина та мережеві запити відсутні.

## Встановлення

1. Закрий Minecraft.
2. Скопіюй **`build/libs/framewatch-0.3.1.jar`** у `.minecraft/mods` **тестового** інстансу.
3. Не використовуй `-dev.jar` або `-sources.jar`; прибери або вимкни старий JAR FrameWatch, не встановлюй одночасно кілька версій. Старий `framewatch.cfg` мігрується зі збереженням видимості блоків, позицій панелей і невідомих параметрів; видаляти його не потрібно.
4. Запусти гру, зайди у світ і зачекай щонайменше 1.5 секунди прогріву.
5. Виконай `/fw status`: `hooks=true` підтверджує основні точки вимірювання. З Angelica 2.2.28 очікуються також `Angelica pacing=true`, `idle-work=true`, `shader-reload=true`.

Мод **не було автоматично встановлено** в жоден інстанс. Для видалення достатньо прибрати JAR із `mods`; конфіг та експорти можна зберегти.

## Керування

| Клавіша | Дія |
|---|---|
| **F7** | Відкрити повне меню налаштувань |
| **F8** | Показати/сховати HUD, збір даних продовжується |
| **F10** | Експортувати весь збережений буфер кадрів у CSV |

Призначення змінюються через **Options → Controls → FrameWatch**. Якщо інший мод уже використовує F7/F8/F10, перепризнач клавішу або використовуй команди. FrameWatch більше не реєструє F9: права панель керується через **F7 → Блоки → Права панель фаз CPU** (англійською: **Blocks → Right CPU phase panel**).

HUD автоматично ховається, коли відкрите будь-яке меню: інвентар, NEI/рецепти, скриня, чат, Escape або налаштування. Єдиний виняток — редактор розташування FrameWatch (`/fw move`), де панелі потрібні для перетягування. Закриття меню повертає HUD; це правило змінює лише відображення, не збір показників чи історію.

Команди клієнтські, без прав адміністратора; `/fw` — скорочення `/framewatch`:

```text
/fw settings
/fw move
/fw preset minimal
/fw preset graph
/fw preset full
/fw scale 0.8
/fw opacity 0.65
/fw toggle
/fw details
/fw reset
/fw export
/fw pause
/fw resume
/fw budget 180
/fw budget 0
/fw position 6 6
/fw status
/fw help
```

`budget` змінює лише лінію бюджету на графіку, **не** ліміт FPS гри. `0` автоматично бере нижче значення між FPS cap та частотою дисплея (60 Гц, якщо обидва невідомі). `position` використовує масштабовані GUI-пікселі.

Конфіг створюється після встановлення: **`.minecraft/config/framewatch.cfg`**. Там можна змінити розташування, розмір графіка, вікно статистики, поріг довгого кадру та прогрів. Зміни HUD через команди, F8 і меню зберігаються між запусками; sliders/toggles меню записуються при закритті екрана. `/fw pause/resume` керує лише поточною сесією збору.

У категорії `hud` конфіга ці параметри мають вигляд:

```text
S:language=uk_UA
B:showMemory=true
B:showDirectMemory=false
B:showProfiler=false
```

Цей приклад обирає українську, лишає RAM купи, ховає Direct і праву панель. Для мови також доступні `auto` та `en_US`. Якщо редагуєш файл вручну, спершу закрий гру.

### Меню налаштувань

Відкриття: **F7**, **`/fw settings`** або **Mods → FrameWatch → Config**. HUD, назви й підказки доступні англійською та українською. **F7 → Вигляд → Мова моду → Українська** (англійською: **Appearance → Mod language**) перекладає тільки FrameWatch, без зміни мови Minecraft або перезавантаження його ресурсів. «Авто» обирає українську для української мови гри, інакше англійську; вибір зберігається в конфігу.

- **Вигляд:** мова моду, масштаб 0.5–2.5, прозорість, тінь тексту, F1, прив'язка кожної панелі до кута екрана, частота оновлення тексту.
- **Блоки:** незалежні FPS, frametime, AVG/MAX/P95/P99/1% low, **RAM (купа JVM)**, **Прямі буфери (не VRAM)**, алокації, GC, графік, події, середовище та **Права панель фаз CPU**. Щоб сховати Direct, вимкни «Прямі буфери (не VRAM)»: RAM купи лишиться видимою, якщо її власний перемикач увімкнено. Вимкнені блоки не залишають порожніх рядків.
- **Графік:** ширина/висота, історія 1–30 секунд, верхня шкала 30–250 мс або Auto, позначки подій, частота оновлення.
- **Вимірювання:** вікно статистики, бюджет FPS, прогрів і поріг довгого кадру. Ліміт FPS гри не змінюється.
- **Розташування:** перетягни ліву/праву панель мишею, Done/Escape зберігає зміни. На маленькому вікні HUD додатково зменшується, щоб уміститися.

Готові набори: **Minimal** — тільки FPS і frametime, без графіка/заголовків/правої панелі; **Graph** — FPS + frametime + графік; **Full** — усі вимірювані блоки. Reset HUD скидає тільки вигляд, не історію/параметри вимірювання та не обрану мову моду. Коли елементи меню не вміщуються, використовуй стрілки сторінок, колесо миші або Page Up/Down.

Опційний блок апаратних сенсорів показує **N/A** для CPU/GPU usage, температур і VRAM: ця версія їх не вимірює. Він вимкнений у готових наборах. Дорогий `getProcessCpuLoad()` не використовується.

## Показники та точність

- **Frame interval:** `System.nanoTime()` між завершеннями CPU-виклику `Display.update`. Включає роботу гри, очікування FPS limiter/VSync та планувальника між цими точками. Це **не** замір фактичної появи кадру на моніторі, input latency чи GPU render time.
- **FPS:** `кількість інтервалів / сума їх тривалостей` за останню приблизно секунду snapshot, а не значення F3 чи середнє від окремих `1000 / ms`. **AVG** використовує повне вікно статистики. **MAX FPS** — обернена тривалість найкоротшого кадру цього вікна, не максимум секундного лічильника F3. **FRAME** — останній виміряний інтервал.
- **Mean/Median/P95/P99/Max:** вікно останніх 5 секунд за замовчуванням. Percentiles — nearest rank; медіана парної кількості зразків — нижній центральний зразок.
- **1% low:** обернена середня тривалість найповільнішого `ceil(n × 0.01)` кадрів. Це не тотожне `1000 / P99`.
- **CPU render:** wall time навколо `EntityRenderer.updateCameraAndRender`; включає клієнтські рендер-проходи/шейдери, але не основний виклик present. Може включати очікування драйвера; це не GPU timer.
- **Tick time:** сумарний wall time клієнтських `runTick` за поточний цикл. Це не серверний TPS/MSPT.
- **Present call:** CPU-час основного `Display.update`, включно з можливим очікуванням драйвера/VSync. Асинхронний backend не гарантує, що GPU вже завершив кадр.
- **Non-pacer wall:** поточний `runGameLoop` мінус перехоплені pacer scopes, з додаванням назад вкладеної роботи `runFrameIdleWork` з чанками. Включає present wait і власну інструментацію FrameWatch. Це не CPU utilization; частини вимірюються на різних межах і **не повинні сумуватися** до frame interval. Якщо optional hooks не працюють, цей показник менш повний — перевір `/fw status`.
- **Heap RAM:** використана / максимальна пам'ять купи Java в HUD. **Direct (not VRAM)** — відстежувані JVM прямі буфери поза купою в нативній оперативній пам'яті. Це **не відеопам'ять**, не вся нативна пам'ять гри й не загальна RAM процесу. RAM купи й Direct можна показувати незалежно.
- **Render-thread allocation:** лічильник виділених байтів лише потоку рендеру за секунду, якщо JVM уже надає його. Мод не вмикає глобальне відстеження алокацій і не підміняє його зміною heap; `n/a` означає недоступність/перший зразок.
- **GC:** повідомлення JVM співставляються з інтервалами кадрів навіть після асинхронного надходження. Час має мілісекундну гранулярність. ZGC concurrent `Cycles` не використовуються для позначок пауз, щоб не подвоювати дані з `Pauses`. Сукупні counters показують активність усіх колекторів. **Збіг GC з кадром не доводить, що GC спричинив фріз**, а тривалість повідомлення не завжди є stop-the-world паузою.

Графік має **фіксовану часову шкалу**, 10 секунд за замовчуванням. На кожну колонку зберігається **найдовший кадр** відповідного проміжку, не середнє: короткі статери не губляться. Проміжки без даних залишаються порожніми й не з'єднуються лінією. Зелене — у бюджеті, жовте — понад бюджет, червоне — записаний long-frame event: тривалість понад `max(longFrameMillis, 2 × budget)`. Верхня шкала за замовчуванням 100 мс; можна вибрати Auto. Піки вище шкали обрізаються візуально з верхньою позначкою, але дані зберігаються повністю. Біла лінія — бюджет. Позначки зверху: жовта GC, блакитна resources reload, фіолетова shader transition, червона long frame.

Права панель **CPU PHASES / ФАЗИ CPU** показує усереднені CPU wall scopes: Tick, Render, Present/wait і Other. Частки нормалізовані за сумою цих scopes, а не GPU/повним frame interval. `Other = max(0, work − tick − render − present)`; через різні межі та можливі накладання це діагностичні частки, не точний розклад GPU-часу. Тут немає вигаданих лічильників entities/chunks або серверного TPS.

## Нюанси Angelica / lwjgl3ify

- HUD малюється перед `Display.update`, після виводу Minecraft framebuffer, **поза кешованим HUD Angelica**. Матриці/атрибути GL відновлюються; використовується її compatibility-GL шлях, без власної заміни shader program/FBO.
- Враховуються scopes `FramePacer.beforePresent/endFrame` та робота чанків, яку Angelica виконує під час очікування кадру.
- Iris reload перехоплюється на вході, нормальному та exceptional exit; generation ID перевіряється перед записом кадру. Це включає перезавантаження того самого shaderpack. Ім'я shaderpack та налаштування опитуються рідше.
- Показуються Java, LWJGL, Angelica, активний shaderpack, cap/VSync, **налаштовані** chunk threads і render-ahead. `Auto` не видається за реальну кількість worker threads.
- Відсутність світу, singleplayer pause, згортання/втрата фокусу та прогрів після переходів виключаються. Resources/shader transitions розривають межу кадрів та перезапускають прогрів; позначка з'являється на першому наступному записаному кадрі. Сам час компіляції не записується як звичайний кадр.
- Реальні довгі кадри після прогріву **не обрізаються** за довільним порогом.
- Якщо очікувана структура класу змінилася, відповідний transformer залишає початковий клас і пише попередження/помилку в лог. `/fw status` показує доступність hooks.

Поки немає GPU timer queries, відсотка GPU/CPU utilization, серверного профайлера, лічильників черги chunk builder та автоматичного висновку про причину фрізу. Це свідомі межі першої версії.

## CSV та приватність

Файли: **`.minecraft/framewatch/exports/framewatch-….csv`**.

Експортуються всі збережені кадри, не лише 5-секундне вікно HUD. Буфер за замовчуванням — 20 000 кадрів (~111 секунд при 180 FPS), найстаріші зразки перезаписуються. Вхід/зміна світу очищає історію; `/fw reset` теж.

CSV має сирі interval/phase values, tick counts, GC overlap та event flags. Метадані містять версії/налаштування, але не серверну адресу, імена гравців, чат, координати, токени чи JVM command line. Дані нікуди не відправляються. Копіювання буфера виконується одноразово на клієнтському потоці за запитом; форматування та запис на диск — окремим daemon-потоком. Для чистого тесту не виконуй export/reset під час ділянки, яку вимірюєш.

## Накладні витрати

- Фіксований primitive ring: без створення об'єктів на кожен запис кадру.
- Графік агрегує піки в заздалегідь виділені масиви приблизно 30 разів/с за замовчуванням; частота налаштовується. Пошук початку вікна — binary search, скануються лише потрібні кадри.
- Фон/графік/смуги малюються одним Tessellator batch на видиму панель замість окремого draw на прямокутник.
- Статистика/текст — 4 Гц за замовчуванням (налаштовується), JVM/env — 1 Гц. Схований HUD не запускає регулярне копіювання/сортування статистики.
- Буфер повідомлень GC обмежений 256 подіями; JVM notifications і lock теж мають власну вартість.

Накладні витрати не нульові. Їх ще потрібно виміряти в реальній GTNH. Порівняй запуск без моду, `/fw toggle` (збір без HUD) та видимий HUD; `/fw pause` зупиняє запис, але JVM polling/notifications та інструментовані виклики залишаються.

## Збірка

Проєкт використовує той самий GTNH Gradle convention, що інші моди в цій робочій папці. Потрібна сучасна Java для Gradle; вихідний bytecode — Java 8.

Windows:

```text
build.bat
```

`build.bat` використовує встановлену тут Java 25, якщо вона є; інакше `JAVA_HOME` має вказувати на JDK, підтримуваний поточною версією Gradle.

Або:

```text
gradlew.bat --no-daemon clean build
```

Тести: ring/window/statistics/CSV/GC notifications та ASM hooks, включно з реальною Forge dev-класою Minecraft і JVM-перевіркою exceptional exits. HUD 0.2.0 користувач перевірив у грі. Нові переклади й налаштування 0.3.x та приховування в GUI у живому Minecraft/Angelica із shaderpack **ще не перевірялися** — потрібен ручний тест. Тести покривають міграцію/збереження конфіга, незалежні RAM/Direct, вибір мови без зміни глобальної локалізації, geometry/drag/scaling, GUI сторінки, видимість HUD у меню й часові buckets. Успішна збірка не є доказом відсутності візуальних проблем чи накладних витрат у грі.
